# Seguridad

No publiques vulnerabilidades, credenciales o datos personales en una incidencia pública. Comunícalos por un canal privado acordado con la persona responsable del proyecto e incluye únicamente la información necesaria para reproducir el problema.

Antes de compartir una revisión:

1. elimina tokens y datos personales del texto, capturas y registros;
2. indica la versión o commit afectado;
3. describe impacto y pasos mínimos de reproducción;
4. evita usar servicios, cuentas o dispositivos reales durante la prueba.

Las credenciales detectadas en un historial deben revocarse o rotarse aunque el historial se reescriba. Reescribir Git elimina referencias publicadas, pero no invalida copias ya descargadas.
